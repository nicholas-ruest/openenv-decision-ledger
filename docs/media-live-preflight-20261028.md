# Read-only media live-evidence preflight, 2026-10-28

`research/media-live-preflight-20261028/live_preflight.py` separates live-evidence/budget feasibility from the explicitly scripted integration fixtures. It performs no file write, credential/account lookup, network call, reservation, execution or submission. A passing preview always returns execution_authorized:false and reservation_performed:false; there is no admitted token to pass to the execution core.

The supplied private snapshot must bind the unchanged native-derived protocol, existing allocation identity/cap and carry-forward spend floor, all pinned parent-file hashes, current receipt and reservation-ledger hashes, actual-credit/usage reconciliation declarations, and a fresh actual provider/model/route fingerprint. Billing observations must be timezone-aware, neither future nor older than the existing two-hour limit, and the receipt timestamp must equal the supplied actual observation timestamp. Refreshing a timestamp alone does not refresh the snapshot. Closed allocations, duplicated/negative/nonfinite reservations, changed caps, prior-spend resets and insufficient actual prepaid balance fail closed. Synthetic-provider/scripted-evidence markers are rejected recursively.

The whole-phase quote reuses scripts/stage-phase-admission.py and its existing10% margin. It conservatively bounds input by512 possible calls times8192context units; output is bounded by16 independent episodes times4096generation units. It does not multiply a whole episode generation allowance by every possible call. The existing helper quotes one output unit per possible call; the preview adds the remaining shared episode output allowance at the same margin. This bounds generation already limited by the frozen protocol, rather than shrinking the experiment or granting a larger allocation. All existing reservations remain counted; no refund, counter reset or new cap is introduced.

Twelve local tests passed using entirely fictional accounting data: exact quote/shared-output arithmetic, insufficient remaining allocation without phase shrinkage, nested synthetic markers, stale/future/naive timestamps, changed allocation/carry-forward spend, missing reconciliation/parents, timestamp-only refresh, duplicate/negative reservations, provider price/route/fingerprint drift, mismatched receipt/ledger hashes, closed/nonfinite allocations and input immutability. No actual account values appear in the tests or this document. CI must be checked before claiming its run passed.

## Limits

Hashes and declarative reconciliation flags bind a supplied snapshot; they cannot prove actual account truth, authenticate a provider or attest that an observation was genuinely collected. External private reconciliation remains required. A future execution adapter must also lock and recheck the existing ledger, verify current provider/source provenance and append each reservation before a call. This pure preview does not replace those operations and is not wired to a paid execution CLI. Provider checkpoint/thinking/Arena-wrapper equivalence remains unattested. Quotes are conservative accounting bounds under supplied prices, not invoice evidence or a billing guarantee.

This change does not claim available live credit, approve a new cap, start a model phase, change a curriculum, tune weights or improve a ranking. Softwarev12 and media-v13 exact requests/images remain frozen and unapproved. No model call, training, dataset replacement or Arena submission occurred. Actual reconciliation and raw-archive/state synchronization remain for permitted daytime ruOS access; no overnight ruOS wake/access was attempted.
