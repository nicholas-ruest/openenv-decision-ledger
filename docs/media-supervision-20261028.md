# Media phase local supervision, 2026-10-28

This adds local execution bounds to the durable media phase without enabling paid execution or changing either reviewed request/image. Source is in research/media-supervision-20261028.

`bounded_native.native_get` is a read-only native preflight client. It accepts only /health and /schema on literal127.0.0.1 with an explicit unprivileged port, uses GET without credentials, ignores environment proxies, refuses redirects, bounds responses at64KiB and wraps the complete connect/read/stream in an asyncio total timeout of at most15seconds. It uses httpx0.28.1. It is not a WebSocket episode client or a provider interface.

`phase_supervisor.supervise` executes one hash-pinned regular worker source with a fresh archive and a finite remaining wall deadline of at most1800seconds. It reuses training.lifecycle.bounded_worker for new-session process-group TERM/KILL cleanup, including descendants when the direct worker exits successfully. Stdout/stderr are discarded. No token, environment values or arbitrary exception text are persisted. A read-only consistency check requires16 checksum-bound episode records and rebuilds the complete phase assessment; an exit0 or a complete.json alone is insufficient. Native replay remains inside the supervised worker; no model/native action is rerun after timeout. Failed/partial archives never authorize automatic resume.

Ten new tests cover the fixed read-only HTTP surface, cancellation of stalled connect and slow streaming, redirects/error/oversized/malformed responses, invalid deadlines/ports, real SIGTERM-resistant worker+child cleanup, orphan cleanup after successful direct-worker exit, full synthetic16-episode phase execution in a real child process and read-only verification, failed workers, source pins, symlink refusal and archive reuse. Descendant assertions inspect actual captured argv and /proc start ticks/state rather than interpreting a PID alone. Zombie processes are distinguished from executing workers.

The first local test invocation failed because the synthetic child inherited relative PYTHONPATH entries after changing to its archive cwd. The fixture now resolves dependency paths before launch; no implementation guard was weakened. It also initially imported a unittest fixture class into the discovery module, unnecessarily rediscovering12 old tests; the unused class import was removed. The final local run counts only10 new tests.

## Limits

This is local inherited-process-group supervision, not a sandbox against a trusted worker that deliberately creates new sessions or remote jobs. Script dependencies must also be immutable and attested externally. Source hash checks do not cryptographically attest the process after launch. Cleanup can take up to the additional0.2second grace plus OS scheduling/reaping overhead. Remote provider cancellation, billed-call termination and container/server cleanup are not established by killing a local client process.

The HTTP tests use deterministic httpx mock transports. Process tests use actual local Python processes and synthetic phase/provider/native callbacks. They establish deadline/cancellation/archive behavior, not model performance, live provider compatibility or software/media transfer. No new model call, training, image experiment, dataset replacement or submission occurred. Both v12 and v13 remain frozen and unapproved. Paid adapters, fresh billing reconciliation, fingerprinting and existing whole-phase accounting gates remain mandatory; there is no paid CLI here. CI results must be verified before claiming success.
