# Local supervisor and reservation consistency

Adds `archive_custody.py`, a pure read-only checker for artifacts that must already have independent Native reconstruction and file/hash leases. It checks the original supervisor lifecycle, worker/parent/source/archive/deadline binding, fresh single-threaded parent, complete eight-assignment finite phase, exact records and unique response identities. It compares before/after ledger **bytes**, retaining the complete original prefix and every old reservation. Each complete archived call must have exactly one newly appended reservation with its original prompt/generation bounds and conservative route-price quote. Dropped, duplicate, unexplained, changed or reused reservation/reply identities refuse validation. Unknown usage or interrupted phases cannot pass this complete-phase check.

This is local consistency, not authentication. Synthetic files can be internally consistent. Even a successful result keeps provider provenance, actual credit, current root spending, execution permission, selection, confirmation authority and improvement false. JSON flags asserting those facts cannot attest them. The function neither opens a provider nor alters receipts, reservations, counters or account observations. No independent provider usage confirmation is implemented by this change.

Seven synthetic custody checks and eight existing pinned MetaHarness reconstruction checks passed locally. The new controls cover retained prefixes/quotes, source/PID/deadline/shutdown changes, missing or uncertain calls, duplicate replies, mismatched replay records, strict counts and refusal to infer credit/provider truth from JSON. No fresh cases or actual reservations were used. The analysis method inventory includes this checker; public seals remain unset, and qualification for the revised source is still required. The original six protected financial/provider files, original worker/supervisor behavior, resource bounds, closed studies and frozen review requests remain unchanged.

The checker is a prepared component. Independently leased real artifacts, original caller integration, fresh reconciliation and complete-plan admission remain necessary. This does not reopen a failed model screen or authorize confirmation, training, an Arena POST or HF replacement. No model gain is claimed.
