# Native two-response software revision candidate

A separate experimental environment lets a model propose a complete repair, receive feedback from only the six visible public examples, and submit a final revised module. The second response automatically terminates. An explicit submit or Arena finish action can end the episode early. Final reward delegates to the existing unchanged hidden-case grader; intermediate reward is always zero. Public-check and neutral-review arms have identical initial reset observations and differ only after the first proposal. Helper-preservation guidance is not added.

The implementation reuses the frozen repair interpreter, write rules, procedural tasks, baseline-adjusted reward and hidden cases. A failed final write cannot accidentally grade the previous accepted module as a full solve. Invalid first code receives a public rejection type and may be revised. Repeated terminal calls cannot change the grade. Reset clears all candidate/session state. The public checker receives only the initial visible examples string, never the hidden task case collection.

Nine controls are provided for both prerequisite tasks, including reference, wrong-to-reference, rejected-to-reference, early finish, invalid final write, no hidden grading on the proposal, terminal idempotence, arm-input equality and reset isolation.
