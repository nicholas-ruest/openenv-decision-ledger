# Output-domain diagnostic: offline prototype

A closed entry-order screen produced a full initial proposal that regressed to a partial final module. The final module returned internal ancestor paths as additional keys; the contract requires exactly the explicit entry paths. Changing only that final output iteration restored full Native reward in a private investigator control. This does not establish a model or leaderboard improvement.

`domain_diagnostic.py` checks key-set equality and actual boolean values without reading supplied expected answers, hidden cases or reference code. It checks the six originally visible input examples and four bounded derived variants per example. A variant moves one entry into a fresh implicit parent while retaining exactly four unique entries, a consistent tree, ASCII canonical paths and the original length/depth/rule limits. Candidate code runs in the unchanged bounded Native interpreter; inputs are copied. The diagnostic never establishes whether otherwise valid boolean decisions are correct.

Four local controls passed in 4.105 seconds on the already-seen qualification fixture. They verify a valid reference, detect exposed internal ancestor keys, show that wrong decisions can still pass the shape check, prove expected-answer independence, retain valid derived-input bounds and input immutability, withhold computed results from the control, and share program unavailability between arms. Oracle modules in these controls are not model solves. No new Native case or provider request occurred. ruOS qualification, a selected live intervention, matched protocol and all execution/admission guards remain pending.

The observed failing revision started from a full proposal. A diagnostic applied only to that first proposal would not catch the later introduced defect. Do not automatically insert this prototype into the closed two-response study, redraw that study, or reopen previously failed preservation/public-pass interventions. Its possible use must be justified as a distinct intervention before any future model comparison.
